# Especificación de Requerimientos de Software (ERS)

## Descripción

En esta asignación, tu equipo elaborará un documento completo de **Especificación de Requerimientos de Software (ERS)** para el producto que están desarrollando en Proyecto 3.

La ERS es el documento fundacional que define **qué** debe construir tu equipo. Debe ser claro, completo y verificable para que el equipo de desarrollo sepa exactamente qué implementar y los evaluadores sepan cómo verificar que cumple con los objetivos.

---

## Objetivos de la Asignación

- Identificar y documentar todos los requerimientos funcionales y no funcionales del sistema
- Definir objetivos claros y medibles (SMART) para el proyecto
- Crear una matriz de trazabilidad que vincule requerimientos con objetivos
- Desarrollar un modelo conceptual UML que represente la arquitectura del sistema
- Demostrar capacidad de análisis y comunicación técnica profesional

## Estructura del Documento

El documento ERS debe incluir las siguientes secciones (ver instrucciones para detalles):

1. **Portada** — Información del curso, equipo, fecha, período
2. **Audiencia** — Identificación de stakeholders
3. **Tabla de Contenidos** — Índice de secciones
4. **Introducción** — Propósito y composición del documento
5. **Participantes del Proyecto** — Lista completa de miembros del equipo
6. **Justificación de la Propuesta** — Problema, necesidad, estadísticas
7. **Descripción de la Propuesta** — Solución propuesta, productos finales, módulos
8. **Objetivos del Sistema** — 1 general + 3 específicos (formato SMART)
9. **Catálogo de Requerimientos:**
   - Perfiles de usuario (actores)
   - Requerimientos funcionales (por módulo)
   - Requerimientos no funcionales
   - Matriz de trazabilidad requerimientos-objetivos
10. **Modelo Conceptual** — Diagrama UML + descripción en prosa
11. **Apéndices** — Información adicional (si aplica)

---

## Estándares de Calidad

Todos los requerimientos deben ser:
- ✓ Claros
- ✓ Concisos
- ✓ Completos
- ✓ Consistentes
- ✓ Verificables
- ✓ Rastreables
- ✓ Factibles
- ✓ Necesarios

---

## Importante

- Todas las referencias y citas deben usar **formato APA**
- El documento debe ser **profesional y bien organizado**
- Cada requerimiento debe incluir **criterios de aceptación claros**
- Los requerimientos deben estar **organizados por módulos**
