# Plan General de Proyecto — Rúbrica

Total de Puntos: 100

| Criterio | Puntos Máx. | Descripción |
|---|---|---|
| **Documento y Estructura** | 10 | La portada incluye todos los elementos requeridos (logo de la Universidad Cenfotec, información del equipo/producto, título del documento, curso, profesores, fecha de entrega, período lectivo). Todas las secciones principales están presentes y lógicamente organizadas. La tabla de contenidos coincide con la estructura del documento. Explicaciones claras en todo el documento con citas APA apropiadas. |
| **Plan de Calidad** | 20 | Estrategia de gestión de calidad claramente definida con procedimientos de control: listas de verificación (con formato de tabla apropiado), diseño de casos de prueba e jerarquía (Test Case → Test Cycle → Test Plan), estrategia de pruebas unitarias con herramientas especificadas, diseño de pruebas de rendimiento con justificación de herramientas. Definition of Done (DoD) como checklist del equipo está incluida. El contenido está bien organizado y claramente explicado. |
| **Plan de Riesgos** | 20 | Identificación comprehensiva de riesgos en todas las áreas (desarrollo, producto, configuración, calidad). Incluye todas las tablas de análisis requeridas: descripciones de riesgos, niveles de impacto con rangos, niveles de probabilidad con rangos, matriz probabilidad-impacto para priorización. Planes de mitigación y contingencia para todos los riesgos de prioridad no baja. Las tablas están claras y bien documentadas. |
| **Plan de Configuración** | 10 | El proceso de control de configuración está claramente definido: herramientas descritas, persona responsable identificada, estrategia de versionado de documentos y software explicada, número de ambientes especificado, procedimientos de respaldo incluidos. Estructura del repositorio y flujo (estrategia de ramas) explicados. Reglas del repositorio definidas para desarrolladores. El contenido está claro y organizado. |
| **Plan de Estándares** | 20 | Estándares detallados en todas las áreas: estándares de interfaz gráfica (paleta de colores, nomenclatura de controles, ejemplos de componentes: botones, textboxes, dropdowns, tablas, etc.), estándares de codificación (convenciones de nomenclatura para código y bases de datos), estándares de documentación (Java Doc obligatorio), estándares de bases de datos. Los estándares son específicos y aplicables a lo largo del proyecto. El contenido está bien organizado y claramente explicado. |
| **Plan de Gestión del Tiempo** | 20 | WBS (Estructura de Desglose de Trabajo) incluido y explicado con delimitación clara de documentos, módulos e historias de usuario. Diagrama de red mostrando precedencia de historias de usuario incluido. Herramienta de gestión de proyectos seleccionada y justificada. Flujo de trabajo para cada historia de usuario definido. Herramientas para minutas, gestión de tareas y administración del proyecto especificadas. El contenido está bien organizado y claramente explicado. |
